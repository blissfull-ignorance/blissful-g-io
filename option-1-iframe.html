Option 1 — the iframe embed

Recommended default. Two moving parts: one hosted file, one HTML block.

How it works on a real WordPress site

  1. Host the file. The Media Library refuses .html uploads (MIME check), so place live.html via SFTP / hosting file-manager at wp-content/uploads/bread-mascot/live.html — static files in uploads/ are served directly. (Alternative: host it on GitHub Pages and point the iframe there; then updates never touch the WP install at all.)
  2. Embed it. In Gutenberg add a Custom HTML block (Elementor: HTML widget, Divi: Code module) and paste the snippet below. Done.
<div style="width:min(460px,100%);margin:0 auto">
  <iframe src="/wp-content/uploads/bread-mascot/live.html"
          title="Bread mascot" loading="lazy"
          style="width:100%;aspect-ratio:1;border:0;border-radius:20px">
  </iframe>
</div>

Live — exactly the markup above, pointed at this demo’s copy of the file

Why reach for this first

  • Sandboxed. The mascot’s CSS and ids can never collide with the theme; the theme can’t break the mascot either.
  • Universal. Works in Gutenberg, page builders, text widgets — and on every WordPress.com plan, because iframes need no unfiltered_html and no plugins.
  • Update = re-upload. New mascot version? Replace one file; every page embedding it picks it up.
  • Cache-plugin safe. Autoptimize / WP Rocket / LiteSpeed never touch iframe content.

About this demo

A static site that imitates a WordPress theme to show four ways of embedding the interactive bread mascot. GitHub Pages has no PHP, so wherever real WordPress would run code server-side, the demo says so and simulates it.

The mascot

  • One self-contained file, ~104 KB
  • No vendor runtime, no CDN, no account
  • Eyes follow the cursor (and get shy)
  • Click the loaf → chomp, the crate → Gockel
  • Leave → he sleeps, return → startle-wake

GDPR note

The mascot makes zero third-party requests and processes no data — embed it on EU sites without a cookie debate.
