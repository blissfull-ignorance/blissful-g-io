Option 4 — the site-wide corner companion

One script include, and every page of the site gets a loaf sitting bottom-right. It is option 1’s iframe, placed by JS instead of by hand.

How it works on a real WordPress site

  1. Put bread-corner-mascot.js (shown opposite) in your child theme, or paste its contents into a WPCode “HTML” snippet set to Run everywhere on the front end.
  2. Enqueue it (or let the snippet print it) — it appends the fixed corner iframe after the page loads.
  3. Host live.html as in option 1; the script points at it.
assets/corner-mascot.js  (this very demo uses it — look bottom-right)
  · injects a fixed 200px iframe (130px on phones)
  · dismiss button remembered via sessionStorage
  · resolves mascot/live.html relative to itself (Pages-safe)
<?php
// child-theme functions.php — enqueue the companion on every page
add_action('wp_enqueue_scripts', function () {
    wp_enqueue_script('bread-corner',
        get_stylesheet_directory_uri() . '/bread-corner-mascot.js',
        array(), '1.0',
        array('strategy' => 'defer'));   // loads after the page paints
});

Etiquette (why there is a × button)

  • A pet that cannot be shooed is a stain. Dismiss → remembered for the session via sessionStorage.
  • Small on mobile (130 px), loading="lazy", and a modest z-index so cookie banners and modals stay on top.
  • Consider showing it only on the front page or blog posts — a checkout page is not a terrarium.

About this demo

A static site that imitates a WordPress theme to show four ways of embedding the interactive bread mascot. GitHub Pages has no PHP, so wherever real WordPress would run code server-side, the demo says so and simulates it.

The mascot

  • One self-contained file, ~104 KB
  • No vendor runtime, no CDN, no account
  • Eyes follow the cursor (and get shy)
  • Click the loaf → chomp, the crate → Gockel
  • Leave → he sleeps, return → startle-wake

GDPR note

The mascot makes zero third-party requests and processes no data — embed it on EU sites without a cookie debate.
