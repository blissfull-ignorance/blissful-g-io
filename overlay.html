Overlay — the mascot behind your content

Wanted: the loaf parked in the lower-right corner, sitting behind the blog text, eyes following the mouse wherever it goes on the page. Possible with method 1? Yes — and this very page is the demo. Scroll, move your mouse, click a word that happens to float over him.

Try it

  • Move the cursor anywhere on this page — his gaze tracks it across the whole body, corner-bound like a garden gnome with a wide neck.
  • Bring the cursor close to him → he looks away (shy, as designed).
  • Click him — or the text lying on top of him → chomp. Click the crate → the Gockel cameos. The click lands on the article (the frame is click-through); the parent hit-tests the corner and forwards it.
  • Move the mouse out of the browser window → he falls asleep. Back in → wake.

How it works — three ingredients

1. A transparent variant of the mascot. The plain live.html paints a dark background (CSS and an SVG backing rect), which would punch an opaque box into the page. The fix is an append-only patch — no surgery on the mascot itself:

<!-- live-overlay.html = live.html + these two appends -->
<style>
  html,body{background:transparent}
  #stage{width:100%;height:100%;background:transparent}
  #stage svg > rect{fill:transparent}   /* CSS beats the SVG fill attr */
  h1,p,#rig,#foot{display:none}
</style>

2. The frame, pinned to the corner behind everything:

/* the frame: fixed to the corner, BEHIND the content, click-through */
#overlay-mascot{
  position: fixed; right: 18px; bottom: 18px;
  width: 230px; height: 230px;
  border: 0; border-radius: 22px; background: transparent;
  pointer-events: none;   /* the page keeps every mouse event */
  z-index: 0;             /* content sits at z-index:1 => he is behind */
}

Your theme’s content needs position:relative; z-index:1 (one CSS line — on this demo the article card is translucent so you can see him through the text; on an opaque card he’d be hidden, which is also “behind”, just less charming).

3. The postMessage bridge. Here is the catch: an iframe that sits behind the page must be pointer-events:none — otherwise an invisible sheet of glass covers the whole site and no link, selection or scroll works anymore. But a click-through iframe also receives no mouse events itself, so the mascot would be blind. The parent page therefore forwards the pointer:

// overlay parent glue (goes in a Custom-HTML block or the same footer
// enqueue as method 4) — the iframe itself is pointer-events:none, so
// the page stays fully usable and WE forward the pointer:
var f = document.getElementById('overlay-mascot'), rect;
function measure() { rect = f.getBoundingClientRect(); }
measure(); addEventListener('resize', measure);
function post(k, x, y) {
  f.contentWindow.postMessage({bread: 'mascot', k: k, x: x, y: y}, '*');
}
f.addEventListener('load', function () { post('enter', 0, 0); }); // wake
addEventListener('pointermove', function (e) {                    // gaze
  post('move', e.clientX - rect.left, e.clientY - rect.top);      // ANYWHERE
}, {passive: true});
addEventListener('click', function (e) {        // chomp/crate hit-test
  if (e.clientX >= rect.left && e.clientX <= rect.right &&
      e.clientY >= rect.top  && e.clientY <= rect.bottom)
    post('click', e.clientX - rect.left, e.clientY - rect.top);   // works
});                                            // even on text above him
document.documentElement.addEventListener('mouseleave',
  function () { post('leave'); });             // out of the window: sleep
document.documentElement.addEventListener('mouseenter',
  function () { post('enter', 0, 0); });       // back: wake with a blink

Inside the frame, a ~20-line listener turns those messages back into synthetic pointermove / pointerenter / pointerleave / click events on the stage — the mascot’s own harness reads only clientX/Y, so it cannot tell the difference. Far-away coordinates are clamped so the gaze saturates at the neck limit instead of spinning. Full bridge source: mascot/live-overlay.html (bottom of the file).

On a real WordPress site

  • Host live-overlay.html like method 1; put the frame markup + parent glue into a WPCode snippet running on the pages you want, or the child theme’s footer.
  • Same-origin not required: postMessage works across origins (lock '*' down to your site’s origin in production).
  • z-index etiquette: stay below modals and cookie banners; if the theme has its own stacking contexts, raise the content’s z-index rather than fighting with negative values.
  • Touch devices: there is no hover — the gaze follows drags and taps land the chomps; consider hiding the overlay below a breakpoint, or keep him as a sleeping corner ornament.
  • Performance: one extra rAF loop; fine on any blog. loading="lazy" and consider content-visibility on long pages.
