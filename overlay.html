Overlay — the mascot on top of your content

Wanted: the loaf parked in the lower-right corner as the topmost layer, floating over the blog text, eyes following the mouse wherever it goes on the page. Possible with method 1? Yes — and this very page is the demo. Scroll, move your mouse, click right on him. (The “behind the text” look is one checkbox away, see below.)

Try it

  • Move the cursor anywhere on this page — his gaze tracks it across the whole body, corner-bound like a garden gnome with a wide neck.
  • Bring the cursor close to him → he looks away (shy, as designed).
  • Click him → chomp. Click the crate → the Gockel cameos. The frame is click-through, so the click also reaches whatever text lies under him — the parent hit-tests the corner and forwards a copy. The page stays fully usable around and underneath him.
  • Move the mouse out of the browser window → he falls asleep. Back in → wake.
  • Scroll — paragraphs slide under him, crisp on top; nothing to slice, nothing to fog.

How it works — three ingredients

1. A transparent variant of the mascot. The plain live.html paints a dark background (CSS and an SVG backing rect), which would punch an opaque box into the page. The fix is an append-only patch — no surgery on the mascot itself:

<!-- live-overlay.html = live.html + these two appends -->
<style>
  html,body{background:transparent}
  #stage{width:100%;height:100%;background:transparent}
  #stage svg > rect{fill:transparent}   /* CSS beats the SVG fill attr */
  h1,p,#rig,#foot{display:none}
</style>

2. The frame, pinned to the corner as the topmost layer:

/* the frame: fixed to the corner, TOPMOST layer, click-through */
#overlay-mascot{
  position: fixed; right: 18px; bottom: 18px;
  width: 230px; height: 230px;
  border: 0; border-radius: 22px; background: transparent;
  pointer-events: none;   /* the page keeps every mouse event */
  z-index: 60;            /* above text and cards; stay below modals */
}

That is all “on top” takes: a high z-index — high enough to beat the theme’s stacking, low enough to stay under modals and cookie banners. Flip the toggle above to send him behind the content instead: his z-index drops to 0, the card rises to 1, and the demo punches a soft round window in the card around him (a radial mask at (--hx,--hy), kept centred on the corner as the page scrolls) so the text fades politely around him instead of slicing across his face.

3. The postMessage bridge. Here is the catch — and it applies in both layers: the frame must be pointer-events:none — otherwise an invisible sheet of glass sits over the corner and no link, selection or scroll works there anymore. But a click-through iframe also receives no mouse events itself, so the mascot would be blind. The parent page therefore forwards the pointer:

// overlay parent glue (goes in a Custom-HTML block or the same footer
// enqueue as method 4) — the iframe itself is pointer-events:none, so
// the page stays fully usable and WE forward the pointer:
var f = document.getElementById('overlay-mascot'), rect;
function measure() { rect = f.getBoundingClientRect(); }
measure(); addEventListener('resize', measure);
function post(k, x, y) {
  f.contentWindow.postMessage({bread: 'mascot', k: k, x: x, y: y}, '*');
}
f.addEventListener('load', function () { post('enter', 0, 0); }); // wake
addEventListener('pointermove', function (e) {                    // gaze
  post('move', e.clientX - rect.left, e.clientY - rect.top);      // ANYWHERE
}, {passive: true});
addEventListener('click', function (e) {        // chomp/crate hit-test
  if (e.clientX >= rect.left && e.clientX <= rect.right &&
      e.clientY >= rect.top  && e.clientY <= rect.bottom)
    post('click', e.clientX - rect.left, e.clientY - rect.top);   // works
});                                            // even on text above him
document.documentElement.addEventListener('mouseleave',
  function () { post('leave'); });             // out of the window: sleep
document.documentElement.addEventListener('mouseenter',
  function () { post('enter', 0, 0); });       // back: wake with a blink

// optional polish for the BEHIND mode: punch a soft round WINDOW in the
// content card around the corner so the mascot never looks "stuck behind
// the card". The card masks a radial hole at (--hx,--hy); we keep those
// in card-local coords as the page scrolls (133 = frame inset 18 + half
// of 230px):
var art = document.querySelector('main article');
function placeHole() {
  var r = art.getBoundingClientRect();
  art.style.setProperty('--hx', (innerWidth  - 133 - r.left) + 'px');
  art.style.setProperty('--hy', (innerHeight - 133 - r.top)  + 'px');
}
placeHole();
addEventListener('scroll', placeHole, { passive: true });
addEventListener('resize', placeHole);

Inside the frame, a ~20-line listener turns those messages back into synthetic pointermove / pointerenter / pointerleave / click events on the stage — the mascot’s own harness reads only clientX/Y, so it cannot tell the difference. Far-away coordinates are clamped so the gaze saturates at the neck limit instead of spinning. Full bridge source: mascot/live-overlay.html (bottom of the file).

The zero-maintenance route: one external script tag

Every ingredient above can be pre-packaged. This site serves mascot-widget.js: it injects the frame, the CSS and the bridge itself, and loads the transparent mascot build from next to itself — the site owner pastes one line into a Custom HTML block, a widget, or the theme’s “footer scripts” setting and never touches code again:

<script src="https://blissfull-ignorance.github.io/blissful-g-io/mascot-widget.js"
        defer></script>
  • No inline JS enters the page content — so WordPress’s display filters (wpautop, wptexturize) have nothing to mangle: this route needs no mu-plugin guard at all.
  • Config via data attributes: data-size, data-inset, data-corner="br|bl|tr|tl", data-front="0" (behind the content instead of topmost), data-raise="article, main" (selectors lifted above him so “behind” works even on themes with unpositioned content).
  • Updates are ours: replace the mascot on this site and every embedding site picks it up on next load.
  • Works on self-hosted WordPress everywhere; on WordPress.com it needs the Business/Commerce plan (scripts are stripped below that).

On a real WordPress site

  • Host live-overlay.html like method 1; put the frame markup + parent glue into a WPCode snippet running on the pages you want, or the child theme’s footer.
  • Same-origin not required: postMessage works across origins (lock '*' down to your site’s origin in production).
  • z-index etiquette: topmost means above the blog, not above everything — keep him under modals and cookie banners (this demo uses 60); if the theme has its own stacking contexts, raise his frame’s value rather than fighting with negative values.
  • Touch devices: there is no hover — the gaze follows drags and taps land the chomps; consider hiding the overlay below a breakpoint, or keep him as a sleeping corner ornament.
  • Performance: one extra rAF loop; fine on any blog. loading="lazy" and consider content-visibility on long pages.
