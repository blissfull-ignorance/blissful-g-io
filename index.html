Four ways to put the bread mascot on a WordPress site

The mascot is one self-contained HTML file: scene data, art and a ~200-line animation core, no dependencies. That makes it embarrassingly easy to embed. This demo shows every method live — and yes, the little loaf in the bottom-right corner of every page is option 4 already working.

Live preview — option 1 (iframe)

1iframe embed

Host live.html, drop a Custom-HTML iframe on any page. Simplest, most robust, works even on WordPress.com free plans.

2inline embed

Paste the mascot’s own style + markup + scripts into a Custom-HTML block. No iframe chrome, blends into the page.

3shortcode

A 20-line plugin registers [bread_mascot] so editors can place the loaf anywhere — posts, widgets, templates.

4corner companion

One enqueued JS file gives every page a fixed-position mascot with a dismiss button. The “site pet”.

All four use the same asset: mascot/live.html (opens standalone). Regenerating the mascot after an art change means replacing that one file — nothing else on the site has to be touched.

About this demo

A static site that imitates a WordPress theme to show four ways of embedding the interactive bread mascot. GitHub Pages has no PHP, so wherever real WordPress would run code server-side, the demo says so and simulates it.

The mascot

  • One self-contained file, ~104 KB
  • No vendor runtime, no CDN, no account
  • Eyes follow the cursor (and get shy)
  • Click the loaf → chomp, the crate → Gockel
  • Leave → he sleeps, return → startle-wake

GDPR note

The mascot makes zero third-party requests and processes no data — embed it on EU sites without a cookie debate.
