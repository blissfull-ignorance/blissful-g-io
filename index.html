The bread mascot on your WordPress site: embedded, or overlaid

The mascot is one self-contained HTML file: scene data, art and a ~200-line animation core, no dependencies. This demo covers both jobs you might want it to do — sitting inside a page four different ways, and floating over the whole site while its eyes follow your cursor.

Live preview — plain iframe

Embedding — methods 1–4

iframe · inline · [bread_mascot] shortcode · corner companion. From “copy-paste one block” to “20-line plugin”, each with a live demo and the real-WP instructions.

Overlay — on top of the content

The mascot floats in the lower-right corner as the topmost layer over your blog text, follows the mouse across the entire page, and still chomps when clicked — method 1 plus pointer-events:none and a postMessage bridge.

Local WordPress — the real thing

Pages can only imitate WordPress. wp_local.py boots genuine WordPress with PHP on localhost and injects this site’s inline fragment into a real wp_insert_post() page — one command, Docker required.

Both embedding and overlay use the same asset family: mascot/live.html (the plain mascot) and mascot/ live-overlay.html (the transparent overlay variant — an append-only patch of the first, see the Overlay page). Updating the mascot after an art change means replacing one file.

Want to see method 2 inside real WordPress? The Local WordPress section documents python3 wp_local.py: it boots an actual WordPress with PHP on http://127.0.0.1:8765 and fetches the inline fragment from this very URL — so the Pages demo and the WordPress proof run byte-identical code.

About this demo

A static site imitating a WordPress theme. Where real WordPress would run PHP server-side, the demo says so and simulates it (GitHub Pages has no PHP).

The mascot

  • One self-contained file, ~104 KB
  • No vendor runtime, no CDN, no account
  • Eyes follow the cursor (and get shy)
  • Click the loaf → chomp, the crate → Gockel
  • Leave → he sleeps, return → startle-wake
